## PART A — Release check (nightly, before triage)
The Changelog DB (collection://{{CHANGELOG_DB_COLLECTION_ID}}) tracks shipped changes: Release status Merged → In review → Live, Live date, Version.
1. Instant-deploy repos (Vercel): entries "Merged" whose commits reached the prod branch → "Live", Live date = merge date.
2. Server repos: entries "Merged" whose commits reached origin/main → "Live" at promotion date. If a /version endpoint exposing the git SHA exists at {{PROD_API_URL}}, verify against it instead of assuming.
3. Mobile (two stages): commits reaching origin/main → read the app version on main → Version = that, status "In review". Then poll stores nightly:
   - iOS: curl "https://itunes.apple.com/lookup?bundleId={{APP_BUNDLE_ID}}&country=gb" → .results[0].version
   - Android: fetch https://play.google.com/store/apps/details?id={{APP_BUNDLE_ID}}&hl=en_GB and extract the version
   "In review" entries with Version ≤ BOTH store versions → "Live", Live date = today. One store only → dated Story note, stay In review.
4. Anything newly Live → include "🚀 Now live: ..." in the Telegram message.

## PART B — Triage
Find tickets via notion-search with data_source_url "collection://{{TASKS_DB_COLLECTION_ID}}" plus a broad teamspace search ({{TEAMSPACE_ID}}); fetch candidates and check properties. Qualifies ONLY if "AI Stage" = "Needs Plan" (empty ≠ qualify) AND Status is Backlog / Shiny Penny / Not started. None → end quietly.

Per ticket, oldest first:
a. "AI Stage" = "Researching".
b. Read the full ticket incl. comments (if previously Blocked, incorporate the answers).
c. Set "Repo" if empty; cross-repo → pick primary, consult SYSTEM.md.
d. Research the actual codebase: files, patterns, prior art (git log), tests, models, gotchas — cite real paths. Notion for product context; web search for third-party APIs.
e. Too vague / contradicts reality → "Blocked" + comment with specific questions. Move on.
f. Else write into the ticket body (replacing any previous plan):
   ## Implementation Plan
   *Generated by Claude (nightly triage) on <date>*
   ### Goal — one paragraph
   ### Context & findings — real file paths, patterns, prior art
   ### Approach — numbered steps naming exact files
   ### Out of scope
   ### Acceptance criteria — [ ] independently testable checkboxes
   ### Success metric — specific analytics event/funnel, search query set, or revenue number + expected direction; add instrumentation to Approach if missing
   ### Test plan
   ### Estimate & risk — S/M/L + main risk
g. "AI Stage" = "Plan Ready".
