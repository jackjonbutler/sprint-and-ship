# /triage — research & plan new tickets

You are the planning stage of the pipeline. Do NOT write any application code.

1. Query Notion "Tasks - Tech" (`collection://{{TASKS_DB_COLLECTION_ID}}`) for tickets where `AI Stage` = "Needs Plan" AND `Repo` = REPO_NAME (from CLAUDE.md). If none, say so and stop.
2. For each ticket, oldest first:
   a. Set `AI Stage` = "Researching".
   b. Fetch the full ticket page. Read the description, any comments, linked pages, and sub-tasks.
   c. Launch a `researcher` subagent to investigate the codebase: relevant files, existing patterns, prior art, gotchas, affected tests.
   d. Launch the `planner` subagent with the ticket and the researcher's findings. If it returns BLOCKED, set `AI Stage` = "Blocked", add a Notion comment with its questions, and move on.
   e. Write the planner's output into the ticket page body (replace any previous plan) using exactly this structure:

      ## Implementation Plan
      *Generated by Claude on <date> — commit <short-sha of HEAD>*

      ### Goal
      One paragraph: what will be true when this ticket is done.

      ### Context & findings
      What the research found: relevant files, patterns to follow, constraints.

      ### Approach
      Numbered steps, each small enough to verify. Name exact files to create/modify.

      ### Out of scope
      What this ticket deliberately does not touch.

      ### Acceptance criteria
      - [ ] Checkboxes, each independently testable.

      ### Success metric
How we'll know it worked in production: a specific PostHog event/funnel, GSC query set, or RevenueCat number, with the direction we expect it to move. If the metric isn't instrumented yet, add the instrumentation to the Approach. Weekly Ship & Learn reports check this after release.

### Test plan
      Unit/integration tests to add or update; manual checks.

      ### Estimate & risk
      S / M / L, plus the main risk and its mitigation.

   f. Set `AI Stage` = "Plan Ready".
3. Finish with a one-line-per-ticket summary: TT-<id> — Plan Ready | Blocked (reason).

Rules: never change `Status` or `Sprint` here — sprint assembly is Jack's job. Never set "Plan Approved" yourself; only Jack does that in Notion.
